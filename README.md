# Chore Wars 🏆

A household chore tracker for two, built as the grown-up sibling of the
[Star Squad](https://github.com/clashi5050/star-squad-bundle) kids' reward
chart. Tap a chore on your phone to earn points, watch the weekly scoreboard
crown whoever's ahead, feed a shared Team Jar toward household rewards, and
cash points in at a prize shop — with confetti and a chime every time.

Unlike Star Squad, this syncs live between two separate phones, so it needs
a small backend instead of being localStorage-only.

## What it does

- **Weekly scoreboard** — each of you has points, a weekly total (crowned
  when you're ahead), an all-time total, and a streak counter for
  consecutive active days. A cosmetic rank/title (Chore Rookie → Legend of
  the Laundry Room) climbs with your all-time points.
- **Task grid** — tap your avatar on a chore to mark it done for the day and
  earn its points; tap again to undo a mis-tap. One completion per person
  per chore per day, resetting automatically at midnight (no manual "new
  day" button needed).
- **Team Jar** — every completed chore also feeds a shared pot (default 3
  pts), so it's competitive individually but cooperative as a household.
- **Prize shop** — editable rewards spent from your own points or the
  shared jar; redeeming triggers a celebration.
- **Celebrations** — canvas confetti, a WebAudio chime, and a rotating cheer
  on completion/redemption.
- **Settings** — no lock-icon/PIN wall like Star Squad (you're equals, not
  parent/kid): edit player names/emoji, add/edit/remove chores and prizes,
  and adjust the jar's per-chore share, all in place.
- **Backup/restore** — export/import the whole board as a JSON file, as a
  local safety net alongside the live sync.

Everything — markup, styles, and logic — lives in `apps/chores/index.html`;
no build step for the frontend.

## Architecture

```
apps/chores/index.html                # the whole frontend, single file
apps/chores/staticwebapp.config.json  # SWA routing/caching config
apps/chores/api/                      # Managed Functions API (Node.js v4 model)
  src/functions/getState.js           # GET  /api/state
  src/functions/saveState.js          # POST /api/state
  src/lib/tableClient.js              # Table Storage client (one row = whole app state)
  src/lib/auth.js                     # shared household-PIN check
Terraform/                            # provisions the SWA + Storage Account/Table
.github/workflows/
  static-web-app.yml                  # provisions the SWA (manual, workflow_dispatch)
  static-web-app-deploy.yml           # deploys app + API (on push to apps/chores/**)
.github/inputs/main/use2/
  staticwebapp.json                   # environment/region matrix input
```

The whole app's state (players, chores, prizes, points, activity log) lives
as one JSON blob in a single Azure Table Storage row — a server-side version
of Star Squad's single localStorage blob. `GET /api/state` reads it;
`POST /api/state` writes it back using the row's ETag for optimistic
concurrency, so if both of you save at nearly the same moment, the loser
gets the winner's state back instead of silently clobbering it. The
frontend polls every 10s and also refreshes immediately after your own
actions, so both phones converge quickly without needing websockets.

There are no user accounts. Both endpoints require an `x-household-pin`
header checked against a `HOUSEHOLD_PIN` app setting — a single shared PIN,
generated by Terraform (`random_password`), that each of you enters once
per phone (cached in that browser's `localStorage`).

Static Web Apps' Free tier includes **Managed Functions**: the API folder
deploys alongside the app content with no separate Function App resource to
provision — Terraform only needs to add the Storage Account/Table and wire
their connection info into the Static Web App's `app_settings`, which the
Functions runtime reads as environment variables.

## Deployment (two-step flow, same as Star Squad)

Terraform provisions the **resource**; content is deployed separately with
a **deployment token** that only exists after the resource is created.

1. Run **Provision Chore Wars Static Web App**
   (`.github/workflows/static-web-app.yml`) from the Actions UI. Pick
   `short_loc` + `environment`.
2. Grab two Terraform outputs:
   - `terraform output -raw api_key` → save as the GitHub secret
     `AZURE_STATIC_WEB_APPS_API_TOKEN`.
   - `terraform output -raw household_pin` → the PIN you'll each enter in
     the app once.
3. Push any change under `apps/chores/**` (or run **Deploy Chore Wars App**
   manually). The app and its API go live at the SWA's `default_host_name`.
4. Open the site on each phone and enter the household PIN when prompted.

### Required GitHub configuration

This repo shares its remote-state storage account with other IaC repos
(fixed in the committed [`Terraform/backend.hcl`](Terraform/backend.hcl)),
so the Terraform state **key** includes the app name
(`${environment}-${short_loc}-chores-static-web-app.tfstate`) to avoid
colliding with unrelated deployments there.

Per environment (e.g. `main`), same OIDC pattern as Star Squad:

| Kind | Name | Purpose |
|---|---|---|
| Variable | `ARM_CLIENT_ID` | OIDC app registration (client) ID |
| Variable | `ARM_SUBSCRIPTION_ID` | Target subscription |
| Variable | `ARM_TENANT_ID` | Azure AD tenant |
| Secret | `TFSTATE_SUBSCRIPTION_ID` | Subscription the tfstate storage account lives in |
| Secret | `AZURE_STATIC_WEB_APPS_API_TOKEN` | SWA content deployment token (set after step 1) |

If you're reusing the same Azure AD app registration as Star Squad for
OIDC, add a federated-credential subject scoped to this repo (`Chores`) —
the existing one is scoped to `star-squad-bundle` and won't authorize
workflows here. Unlike Star Squad, this repo's Terraform has no dependency
on the private `iac-modules` repo, so no `GH_PAT` secret is needed.

- **Pin the deploy action SHA.** `static-web-app-deploy.yml` currently uses
  `Azure/static-web-apps-deploy@v1` with a placeholder — replace with a
  full commit SHA from the action's releases page.
- **Region support.** SWA Free tier is only available in some regions; if
  `location` in the JSON input isn't supported, `terraform apply` will fail.

## Privacy note

This repo is public, so `index.html` ships with placeholder names
(`Player 1`/`Player 2`) rather than real ones. Rename via Settings after
opening the app — that write goes to the shared server state, not this
repo, but it's still visible to anyone who has (or guesses) the household
PIN. Don't hardcode real names into `index.html`, and treat the PIN like a
lightweight shared password, not real authentication.
